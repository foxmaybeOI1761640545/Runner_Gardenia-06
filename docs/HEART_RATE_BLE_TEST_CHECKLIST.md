# Runner Gardenia 真实心率带验收清单

状态：**尚无真实心率带接入，以下硬件项目均待验证。** 自动化证据只覆盖 SIG 解码、可控 BLE 传输/状态替身、API 35 本地数据库、真实界面和截图；模拟器截图中的设备与 BPM 明确为测试夹具。

记录手机型号、Android 版本、应用版本/Code、心率带型号/固件、测试时间与结果。仅使用已验证的正式签名 `com.fox.runner` APK；Debug 包是独立测试应用。

1. 佩戴并开启心率带，按设备要求湿润接触面，关闭其他应用对该心率带的占用。
2. 打开应用的“传感器设置 → 心率 → 所选心率带”。授予附近设备权限；旧 Android 扫描还需要位置权限/位置服务。预览复用现有运动传感器前台服务，因此沿用该服务已有的位置权限要求，不新增后台位置权限。
3. 扫描并检查标准 Heart Rate Service 设备的名称、RSSI，手动选择目标。点“再次扫描”确认不会重复条目，也不会自动连接附近所有设备。
4. 点“连接／重新连接所选心率带”，在设置中的预览确认 BPM 与心率带一致、状态已连接、更新时间持续刷新。此时不要开始运动，确认没有新运动记录被创建。预览只在内存中显示。
5. 返回并开始运动记录，确认 GPS/原有数据正常、实时心率随设备数据更新；不连接心率带也能正常记录 GPS。
6. 连续记录至少十分钟，静止与运动均覆盖；检查时间图中的完整心率样本、最低/平均/最高值和缩放/平移。相同 BPM 的连续通知必须保留，重复快照不应重复保存。
7. 暂停记录并继续接收心率，再恢复。暂停区间不得增加原始记录样本，恢复后的数据属于同一运动；开始前的预览样本不能被补写进新运动。
8. 短暂关闭心率带或离开范围，确认旧 BPM 清空/过期，运动继续，状态提示重连；重新开启后确认按 1/3/5/10 秒上限退避恢复，曲线在连接边界断开。分别检查时间轴与距离轴。
9. 点“断开心率带”，等待至少 30 秒并切换蓝牙电源，确认不会自行重连。设备选择仍被记住；仅在再次点击连接／重连后恢复。不能因此断开其他类型传感器或结束 GPS 运动。
10. 在 Android 设置中关闭蓝牙、拒绝/撤销附近设备权限，返回应用检查提示与恢复流程，确认应用不崩溃。不要同时撤销 GPS 权限，以免混淆两个独立场景。
11. 结束运动，重新打开历史记录，检查心率曲线、断连缺口和统计；重启应用后再次检查。没有心率的旧记录仍应可读。
12. 从有效旧版 v0.1.0-rc1.4 升级到新的同包名/同证书 APK，保留旧运动并检查数据库升级。**这项真实安装升级尚未完成；CI 已验证数据库 v42→v43 的保留迁移。**
13. 对设备提供的可选字段分别记录证据：8/16-bit BPM、接触标志、Energy Expended、RR（精确 1/1024 秒单位）、Body Sensor Location、Battery。设备未提供时记为“不支持/未提供”，不能凭型号假定 RR 存在，也不能将单元测试当作硬件协议抓取证据。
14. 检查亮色/暗色、较窄屏幕、后台/锁屏和长时间记录的电量/连接表现。完成预览但不开始运动时，按原有首页传感器开关停止不再需要的传感器服务。
15. 确认没有网络上传，GPX/KML/CSV 仍按原逻辑导出 BPM；设备地址和原始 RR 元数据保留在本地数据库。对外分享测试结果时使用脱敏截图。
